More importantly, we should solve the field-compatibility problem we identified earlier. Right now the deterministic validator answers, “Did this value come from trusted information?” It does not properly answer, “Does this value belong in this particular field?” So with a request such as “John is 42 years old,” an LLM could theoretically propose filling a Name field with "42". Because "42" appears in the user request, the current deterministic validator can approve it immediately. The Validator LLM would never even get a chance to catch it. This is the most important correctness gap I see in the current discovery system, so I would make this our next coding task.

While working on that validation layer, I would also strengthen post-action validation slightly. Right now a FILL is automatically considered successful if Playwright didn't throw an exception. Eventually we should verify that the target field actually contains the intended value after filling it. Similarly, the current FINISH validation mostly verifies numeric facts. That's acceptable as an initial implementation, but it isn't strong enough to be the final version because final answers can contain names, statuses, addresses, descriptions, and other nonnumeric facts. We don't have to solve all of that immediately, but it belongs in the same validation-hardening phase.
